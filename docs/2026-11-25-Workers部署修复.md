# Workers 静态模型体积修复

2026-11-25（北京时间），基于 main 的 d0067f5 修复两份正式 GLB 超出 Workers 单文件限制的问题。gzip 较小并不能让同目录的原始 GLB 免于体积检查；两种文件都必须保留，因为浏览器是否支持 DecompressionStream 决定游戏走哪条加载路径。

## 处理方法与取舍

先用 glTF Transform CLI 4.5.0 inspect 定位体积，再用 Sharp 对嵌入 PNG 做无损重压。仅无损重压仍超过目标，因此把不透明的基础色贴图转为 JPEG，quality=95、chromaSubsampling=4:4:4、mozjpeg=true。内马尔保留 4096×4096 身体贴图与 2048×2048 头部贴图；C 罗全部贴图保留 2048×2048，法线与金属/粗糙度贴图仍为无损 PNG。

仅重新打包图片 bufferView 及其偏移，未减面、重命名或改变骨骼、节点、材质和动画。所有非图片 bufferView 逐字节一致，场景、网格、蒙皮、动画、材质等 JSON 结构一致。扩展仍只有 KHR_materials_specular，无 required 扩展，现有 Three.js r187 GLTFLoader 已支持，不需要改 world.js 或加入解码器。

gzip 使用 `gzip -n -9 -c` 从新 GLB 重新生成，避免带入文件名和时间戳。新增 wrangler.jsonc 明确 Worker 名和静态目录；.assetsignore 仅排除开发元数据与工具目录，没有排除正式模型。
