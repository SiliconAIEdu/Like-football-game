亚马尔槽位 · 原创金发球员可动版 V1

本版将已确认的原创金发红蓝球衣静态模型接入实际比赛。
roster.js 指向 assets/yamal-playable-v1.glb，不再引用贝林厄姆。
头部、球衣、发型使用该模型自身贴图，不叠加旧角色程序化改脸、卷发和条纹。

资产：27 根骨骼、约 11 万三角面、8 个肩部方向修正目标；走路、跑步、停步、转向、射门、扑救和庆祝使用角色专属动作。GLB 与 gzip 同步。2048px JPEG 贴图压缩降低下载量。
静态原件保留在项目外 output/原创金发球员-3D-Demo，未覆盖。

构建依赖：Blender bpy 4.5.4、NumPy、SciPy。用具备这些包的 Python 执行。
环境变量 SOURCE_GLB 指向冻结的 player-demo.glb，GAME_ROOT 指向 play-v3。
顺序：prepare.py → build.py → shapes.py → animate.py → plant-support.py → export.py → validate_render.py。
中间 .blend 与渲染输出留在本目录但不提交。源静态模型需另行提供；本目录不是完全独立的迁移包。

绑定根据此角色重新拟合。手臂以低于 1.20m 的独立网格区域作为种子，肩胸过渡按邻接权重求解，避免生成网格腋下粘连把下半身误分配给手臂。手腕和腿部关节按新比例调整；短裤裆部保留骨盆权重。
动作参考既有 ronaldo-natural.glb，只重定向姿态，不复制其身体比例。肩带运动烘焙在专属动作中，肩部修正由 shoulder-deformation.js 在骨骼/IK更新后驱动。
射门支撑脚按源根轨迹约束，并修正鞋底高度；触球数据单独写入 yamal-playable-v1-contact.json，仅应用于该角色，NPC 与其他球员保留原合同。动画播放优先使用角色自身动作，不再次添加旧骨架的位置偏差。

验证：npm test 包含模型皮肤权重、专属动作优先规则、GLB/gzip 一致性和触球距离检查；validate_render.py 重新导入导出GLB，检查走跑/射门/庆祝与三平面×六角度共18组肩部姿势。报告 JSON 与源脚本一同保留。
18组肩部检查要求胸部中央位移低于5mm、最大网格边长增量低于20cm，该阈值用于阻止严重拉扯，不代表所有褶皱已达到写实美术质量。
实际游戏中检查选人、加载、上场、射门得分和控制台错误；yamal-motion-study.html 使用相同 FootballWorld、GLB 和修正逻辑，便于逐动作查看。

限制：当前为可玩的生成角色美术版本；手指未逐指绑定，面部没有独立眨眼表情，极端高举时袖口和腋下褶皱仍有精修空间。不是临床肌肉仿真或独立布料模拟，也不声称是真人肖像。
